# First maintenance audit

Source baseline: `6349863`, 2026-11-03. This is a source audit, not a claim of
measured application latency or complete extension conformance. Findings below
name the baseline code path so later refactors do not erase their rationale.

The first pass preserves application identity, stored data, existing workflows,
IME and HyperKey behavior. It extracts ownership where a concrete failure can
be tested. Large-file size alone is not a reason to rewrite a feature.

## Selected work and acceptance

1. **Credential durability.** `src/main/safe-storage.ts` mutates cached secrets
   before `persistVault`; a failed save followed by the same value returns true
   without retrying disk persistence. `settings-store.ts` trusts success before
   redacting the legacy copy. Direct overwrite and treating every read error as
   an empty vault add data-loss paths. Accept only after failure/retry/delete
   tests prove that cache and return values reflect durable state, replacement
   preserves the old file on failure, and unreadable encrypted entries survive.
   Keep the format and existing encryption/fallback behavior.

2. **Extension installation transactions.** The bundle, source and Git install
   paths in `src/main/extension-registry.ts` delete `installPath` on errors that
   can occur before a backup exists. Their cleanup also deletes a backup when
   restoration fails. Build in staging using `buildAllCommands`' path override,
   then replace under a single owner. Acceptance covers acquisition/build/copy
   failure, rollback failure, initial install cleanup, and same-name concurrency.
   Validate extension names and tar paths as part of this responsibility: the
   old name regex accepts `.` and `..`, and the extractor joins unchecked paths.
   Temporary-directory tests must prove outside sentinel files remain intact.

3. **Command catalog freshness.** `src/main/commands.ts` invalidates cached
   results without retiring in-flight discovery. Old work can publish a fresh
   cache after an install or removal. Quick Link mutation handlers in `main.ts`
   notify before refresh, allowing the renderer to read the stale fallback with
   no completion notification. Acceptance covers overlapping invalidations,
   deduplicated discovery, immediate stale reads, failed-refresh retry, and
   notification only after valid publication. Preserve ranking and command IDs.

4. **Background scheduling.** `hooks/useBackgroundRefresh.ts` recreates every
   interval on command-list updates. A short-interval script refreshes that list
   and can indefinitely postpone a long-interval extension. Async ticks can
   overlap or dispatch after removal. Acceptance uses controlled time and
   promises to prove stable due times, one run per identity, current metadata,
   and no obsolete dispatch after removal or disposal. Preserve preference,
   argument, and menu-bar visibility checks.

5. **Nonblocking AppleScript.** `run-applescript` in `src/main/main.ts` declares
   an async handler but calls `spawnSync`, blocking Electron during execution.
   Extract asynchronous execution while preserving stdin, language selection,
   output formatting, timeout normalization, and error semantics. Acceptance
   includes a live subprocess heartbeat, timeout and output limits, Unicode,
   failure paths, and real macOS `osascript` cases. Other synchronous OS queries
   remain separate follow-up work.

6. **Unicode file search.** `src/main/file-search-index.ts` splits on
   `[^a-z0-9]`; a Chinese-only query becomes empty and returns before Spotlight,
   while Chinese-only directories are omitted. Acceptance searches a temporary
   index through production entry points for Chinese, Japanese, Korean, mixed
   names, accents, English, and path queries. Preserve ordering and root policy;
   leave input-method event handling unchanged.

7. **Maintenance entry points.** Replace duplicated agent instructions and
   unverified “implemented” tables with a shared entry, source ownership map,
   compatibility limits and validation guide. Preserve unique i18n and silent
   command rules. Expose renderer type diagnostics; Vite success alone does not
   establish type correctness.

## Follow-up work requiring separate scope

### File index roots reached through symlinks

`file-search-index.ts` compares a walked directory's real path against the
configured home string. If that home contains a symlink, the resolved path can
appear to be outside the home and the entire walk is skipped. The macOS temporary
fixture exposed this existing behavior through `/var` and `/private/var`.
Support for aliased home paths needs separate physical-root and display-path
ownership, with tests for in-root links, escaping links, cycles, tilde display,
watch events and protected roots. Do not remove the confinement check to accept
an aliased path.

### Extension identity across async work

`raycast-api/context-scope-runtime.ts` holds a shared context stack across
Promises. If A starts, B starts, and A finishes first, A can read B's identity;
A's restore does not remove its non-top entry. Later B restores stale A.
Preferences, environment, storage and OAuth can be affected. Removing arbitrary
stack entries fixes retention but does not establish async identity. Design the
identity binding first, then verify a foreground extension with two background
menu-bar extensions across module initialization, render, effects, actions,
timers, and awaited continuations in real Electron.

### Async hook requests

`raycast-api/hooks/use-promise.ts`, `use-cached-promise.ts`, and `use-fetch.ts`
guard only mounted state. Older results/errors can overwrite newer requests or
append pages to a different query. `usePromise` does not use its abortable option;
`useCachedPromise` replaces rather than aborts the previous controller and does
not rerun when only `execute` changes. Define request invalidation separately
from extension identity. Test actual hooks with reverse completion, execute
transitions, callback changes, pagination, and unmount before changing mutate
or storage semantics.

### Storage compatibility and cache ownership

The `Cache` class in `raycast-api/index.tsx` keys only by namespace, so default
instances from different extensions share data. Replacement counts old and new
values together; eviction repeatedly scans all values and accepts an oversized
item. `LocalStorage` and `hooks/use-local-storage.ts` also use different key/value
formats; the hook emits change events but does not subscribe. A fix must define
legacy-key ownership and migration without deleting ambiguous existing data.
Test multiple instances and extensions, updates, capacity, and subscriptions.

### File icon request ownership

`App.tsx` and `FileSearchExtension.tsx` request every result icon repeatedly and
retain historical paths without a bound. The main handler calls `app.getFileIcon`
and serializes each request. A shared bounded loader should deduplicate in-flight
requests, retry failures, preserve visible/pinned icons, and ignore obsolete
query completions. Validate native call counts and retained entries. The command
icon interning map in `App.tsx` also replaces changed icons with the first cached
value for an ID; test an icon update before changing that behavior.

### Extension timers and native process lifetimes

`ExtensionView.tsx` adds timeout and RAF handles to sets without removing them
after execution. A long-lived extension accumulates completed handles. Test
completion, cancellation and disposal through one timer owner. This does not
solve all timer isolation: Node timer imports and `globalThis` can bypass the
current registry and have additional handle semantics.

Native speech process exit handlers in `main.ts` can clear global state after a
replacement process starts. Several spawn paths lack an error listener. Scope
that work around process identity, startup failure, pending requests and stop;
test old-exit/new-start ordering before changing speech protocols.

### AI chat session lifetime

`hooks/useAiChat.ts` sends IPC and persists from React state updaters. Stop, new,
select and exit cancel without saving the partial turn; main suppresses later
done events after abort. Its Escape listener depends on messages rather than
active view. Test exactly-once submission, partial persistence, late events,
conversation switching and keyboard ownership in a dedicated lifecycle change.

### Root search work and diagnostics

`hooks/useLauncherCommandModel.ts` applies older filtering and newer scoring in
the same pipeline. The older path still influences calculator fallback, so
removing it requires behavior cases for aliases, transliteration, calculator,
always-on-top commands, browser groups and files. Its `SC-RANK2` debug effect
also sends query/title data over Whisper IPC. Remove diagnostic work deliberately
and measure scoring invocations rather than assuming a latency improvement.

### Validation debt

The baseline checks main TypeScript and bundles the renderer without checking
renderer types. Several legacy tests inspect source strings rather than execute
behavior. The translation checker tolerates non-strict locale gaps, including
two known Italian keys. Establish explicit diagnostics and replace structural
tests as the owning behavior is changed; do not claim test coverage from a
matching function name in source.

The first renderer diagnostic collected 46 errors at `fd8c4f4`, whose application
source is unchanged from this audit baseline. Examples include an undefined
`setCapturePreviewClearTimerRef` in `CameraExtension.tsx`, browser-search payload
type mismatches, a circular `MessageTree` alias, and inconsistent runtime type
declarations. The uploaded diagnostic artifact and job log are the full list.
Resolve these through their owning modules before making the renderer type check
a blocking gate; a non-blocking report is only visibility into the debt.
